# OpenVideo2Text 浏览器扩展

在视频页面上点一下就把文字提出来，不用复制粘贴链接。

扩展本身**不做任何解析或转写** —— 转写是本地服务在跑（那是 Python + Whisper/FunASR，
扩展装不下）。它只做两件事：

1. 在你**已经登录好的页面**里，把媒体地址和元信息读出来
2. 丢给本机服务，展示结果

## 为什么要有它

不是为了「省一次粘贴」，而是因为**人在页面上**这件事本身有价值：

| | 走本地网页 | 走扩展 |
|---|---|---|
| 小红书 `xsec_token` | 从地址栏复制，可能已经过期 | 就在当前页面，永远是新鲜的 |
| 小红书媒体地址 | 得重新请求一次页面，可能拿到降级页面 | 直接读页面里的 `__INITIAL_STATE__`，就在手边 |
| B站 AI 字幕 | 需要浏览器登录态 | 同上，且不用管你登录在哪个浏览器 |

实测过：同一条小红书链接，十分钟内从可用变成不可用（服务端返回不含笔记数据的
降级页面）。在页面上取就没有这个问题。

## 安装

> 需要 Chrome / Edge 等 Chromium 内核浏览器。

1. **先启动本地服务**：在项目目录双击 `run.command`，看到 `http://127.0.0.1:8756` 起来即可
2. 打开 `chrome://extensions`，右上角打开「开发者模式」
3. 点「加载已解压的扩展程序」，选择这个 `extension/` 目录
4. 工具栏上会出现蓝色的喇叭图标

> 修改代码后记得回扩展页面点一下刷新按钮（插件图标旁边的 ⟳）。

## 使用

1. 打开 B站 / 小红书 / YouTube 的视频页面
2. 点扩展图标 —— 它会显示识别到的平台和标题
3. 选语言和引擎，点「提取文字」
4. 出结果后可以直接下载五种格式

**关掉弹窗不会中断任务。** 任务由本地服务持有，重新打开弹窗会接着显示进度
（job id 存在 `chrome.storage.local` 里）。

## 权限说明

只申请了三个权限，都是最小必要的：

| 权限 | 用途 |
|---|---|
| `activeTab` | 只在你点击扩展时，读取**当前这一个标签页**。不是「读取所有网站」 |
| `scripting` | 往页面里注入读取函数 |
| `storage` | 记住任务 id，让弹窗关掉再打开能接着看 |

没有后台常驻脚本，没有内容脚本注入到每个页面，也没有向任何外部服务器发请求 ——
唯一的网络目标是 `127.0.0.1:8756`（你自己的电脑）。

## 实现上的两个坑

**1. 必须注入到页面主世界（`world: 'MAIN'`）**

内容脚本默认跑在隔离世界里，**读不到页面的 JS 变量**，而小红书的
`window.__INITIAL_STATE__` 就在那里。这也是 bilibili-subtitle 为什么要搞一整套
跨世界消息层的原因。我们用 `chrome.scripting.executeScript` 的 `world: 'MAIN'`
一次性解决，不需要常驻脚本。

**2. 本地服务要允许私有网络访问**

Chrome 对「网页/扩展访问 localhost」有额外策略，会发一个带
`Access-Control-Request-Private-Network` 的预检请求。服务端必须：
- 回显具体来源（不能用 `Access-Control-Allow-Origin: *`）
- 回 `Access-Control-Allow-Private-Network: true`

缺任何一个预检都返回 400，扩展就再也连不上。这两个在 `app.py` 里通过
`CORSMiddleware(allow_origin_regex=..., allow_private_network=True)` 配好了。

## 测试

提取逻辑的测试跑在 node 里，不需要浏览器：

```bash
node test/extract.test.js
```

它把一个假的 `__INITIAL_STATE__` 喂给提取函数，覆盖了小红书各种字段缺失的情况。
还会验证函数**不引用任何外部变量** —— 它会被序列化送进页面执行，引用外部作用域
不会在开发时报错，但上线后一定失败。
